title: PostHog

PostHog is an open-source product analytics platform that also offers feature flags and session replay. It supports both browser and backend tracking, so the same trakoo event definitions work on the client and the server.

## When to use it

- You want product analytics that span the browser and your backend.
- You need a single tool for events, funnels, feature flags, and session replay.
- You want to self-host or keep data in a specific region.

If you only need lightweight page views, a privacy-friendly option like [Pirsch](/docs/providers/pirsch) or [Visitors](/docs/providers/visitors) may be a better fit.

## Installation

The PostHog providers ship in the `@trakoo/posthog` package. Install it alongside trakoo and only the PostHog SDK for the side you use — `posthog-js` for the client, `posthog-node` for the server.

```bash
# Client
pnpm add trakoo @trakoo/posthog posthog-js

# Server
pnpm add trakoo @trakoo/posthog posthog-node
```

## Client-side usage

Use `PostHogClientProvider` from `@trakoo/posthog/client`. It accepts every option from the PostHog JS SDK, so anything you can pass to `posthog.init()` works here.

```typescript title="lib/analytics.ts"
import { createClientAnalytics } from "trakoo/client";
import { PostHogClientProvider } from "@trakoo/posthog/client";
import { appEvents } from "@/lib/events";

export const analytics = createClientAnalytics({
  events: appEvents,
  providers: [
    new PostHogClientProvider({
      token: import.meta.env.VITE_POSTHOG_KEY,
      api_host: import.meta.env.VITE_POSTHOG_HOST,
    }),
  ],
});
```

### Browser instance isolation

Every `PostHogClientProvider` uses its own named PostHog SDK object by default.
That keeps each provider's live configuration and calls to `identify`,
`capture`, and `reset` isolated from other Trakoo instances.

Most applications should omit `instanceName`. It is an advanced escape hatch
for deliberately selecting a PostHog named instance:

```typescript
new PostHogClientProvider({
  token: import.meta.env.VITE_POSTHOG_KEY,
  instanceName: "marketing",
});
```

Reusing the same `instanceName` opts providers into sharing that named SDK
object. The instance name does not change PostHog's persistence semantics:
stored identity continues to use the project token by default, or
`persistence_name` when you configure one. Generated instance names therefore
do not make browser identity disposable across normal navigation or reloads.

## Server-side usage

Use `PostHogServerProvider` from `@trakoo/posthog/server`. Server analytics is stateless, so pass user context with each call.

```typescript title="lib/server-analytics.ts"
import { createServerAnalytics } from "trakoo/server";
import { PostHogServerProvider } from "@trakoo/posthog/server";
import { appEvents } from "@/lib/events";

export function createRequestAnalytics() {
  return createServerAnalytics({
    events: appEvents,
    providers: [
      new PostHogServerProvider({
        apiKey: process.env.POSTHOG_API_KEY!,
        host: "https://us.i.posthog.com",
      }),
    ],
  });
}
```

```typescript title="app/api/signup/route.ts"
import { createRequestAnalytics } from "@/lib/server-analytics";

export async function POST() {
  const analytics = createRequestAnalytics();

  try {
    await analytics.track(
      "user_signed_up",
      {
        plan: "pro",
      },
      {
        userId: "user_123",
      },
    );

    return Response.json({ ok: true });
  } finally {
    await analytics.shutdown();
  }
}
```

For server `pageView` calls, PostHog uses `context.user.userId` as the distinct
ID, falls back to the email supplied in that call, and otherwise records the
page view as anonymous. Server identity is never retained between calls, so
include the relevant user context on every page view that should be attributed
to a user.

:::warning[Match shutdown to PostHog ownership]
PostHog's Node client queues events. A request-owned client must shut down before its request finishes so its queue can be delivered. A reusable process-owned client shuts down only during process teardown, never after each request. See [Client vs Server](/docs/core-concepts/client-vs-server) for the full picture.
:::

## Configuration

`PostHogClientProvider` forwards all [PostHog JS options](https://posthog.com/docs/libraries/js). The keys you'll set most often:

<TypeTable
  type={{
    token: {
      type: "string",
      required: true,
      description: "Your PostHog project API key.",
    },
    api_host: {
      type: "string",
      default: "https://us.i.posthog.com",
      description: "PostHog instance URL. Change this for EU or self-hosted.",
    },
    debug: {
      type: "boolean",
      default: "false",
      description: "Log PostHog SDK activity to the console.",
    },
    enabled: {
      type: "boolean",
      default: "true",
      description: "Set to false to disable the provider without removing it.",
    },
    instanceName: {
      type: "string",
      required: false,
      description:
        "Advanced: select a named PostHog SDK instance. Omit for an isolated Trakoo-managed instance.",
    },
  }}
/>

`PostHogServerProvider` forwards all [PostHog Node options](https://posthog.com/docs/libraries/node). The common ones:

<TypeTable
  type={{
    apiKey: {
      type: "string",
      required: true,
      description: "Your PostHog project API key.",
    },
    host: {
      type: "string",
      default: "https://us.i.posthog.com",
      description: "PostHog instance URL. Change this for EU or self-hosted.",
    },
    flushAt: {
      type: "number",
      default: "20",
      description: "Number of queued events that triggers a flush.",
    },
    flushInterval: {
      type: "number",
      default: "10000",
      description: "Milliseconds to wait before flushing queued events.",
    },
  }}
/>
